## 〇、启动环境（先做这一步）

**后端**（终端 1，在 `backend` 目录）：
```bash
pip install -r requirements.txt   # 首次安装依赖
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8899
```
- 健康检查：浏览器打开 `http://127.0.0.1:8899/api/health`，应返回 `{"status":"ok"}`。
- **验证连接池生效**：启动日志无异常即正常；可观察 `backend/quant.db` 已存在（K 线磁盘缓存复用）。

**前端**（终端 2，在 `frontend` 目录）：
```bash
npm install   # 首次需安装依赖
npm run dev
```
- 浏览器访问 `http://localhost:5899`。

> 前端直连后端 `http://127.0.0.1:8899/api`。涉及写操作（保存/训练/报告导出）需先登录。

**操作步骤**：

**代码核对**：`frontend/src/views/QuoteView.vue:44` 请求参数 `days: 500`。

### V2 回测/回归历史长度上限放开 ✅

**窗口**：分层回测 / 多因子回归 / 回归

**操作步骤**：
1. 各页面找到「历史长度(日)」输入框。
2. 输入 `2000` → 预期结果：
   - ✅ 不再被输入框 `max` 拦截（修改前上限 360/300）；
   - ✅ 点「运行回测 / 运行回归」可正常提交，后端返回更长历史窗口的结果。

**代码核对**：`BacktestView.vue:301`、`FactorRegressionView.vue:103`、`RegressionView.vue:125` 均为 `max="2500"`。

### V3 后端默认历史天数 ✅

### V4 长历史不再被适配器截断 ✅

1. 浏览器访问：`http://127.0.0.1:8899/api/kline?code=sh600519&days=1500`

   - ✅ 返回超过 1000 根 K 线（修改前新浪单笔封顶 1023、东财封顶 500，大请求被静默截断）；

## 四、配置项速查

| 变量 | 默认值 | 说明 | 生效方式 |
|---|---|---|---|
| `QUANT_RATE_ANON` | `300` | 匿名用户读接口限流（次/分钟） | 环境变量，重启后端 |
| `QUANT_RATE_USER` | `2000` | 登录用户读接口限流（次/分钟） | 环境变量，重启后端 |
| `QUANT_CORS_ORIGINS` | 本地 5899/5173 | CORS 白名单（既有） | 环境变量，重启后端 |

示例（Windows CMD）：
```bat
set QUANT_RATE_ANON=500
python -m uvicorn app.main:app --host 127.0.0.1 --port 8899
```

## 五、常见问题排查

| 现象 | 排查方向 |
|---|---|
| 修改后启动报错 | 确认后端依赖完整（`pip install -r requirements.txt`）；共享连接池按 event loop 隔离，正常启动不受影响 |
| 长历史仍拉不到 1000+ 天 | 腾讯主源单次请求有服务端上限时，首次返回较少属正常；**重复**访问更大窗口会基于 `kline_cache` 累计补齐 |
| 大池选股仍慢 | 体感来自第三方接口本身；可改用小池验证并发提升（对比修复前耗时）；日志中「拉取K线失败」增多则可能是限流，可提高 `QUANT_RATE_ANON` 或登录使用 |
| 偶发 429 | 未登录且 1 分钟内请求超 300 次；登录后上限 2000/min |
| 回测历史长度填了 2500 很慢 | 属预期（数据量≈10 年）；建议先在 500~1000 验证，需要更长历史再放大 |
