# ML 训练 / 验证 / 调参流程说明

> 回答："机器学习是不是用一段历史训练、用另一段历史验证、再手动调参"——**是的**。
> 本说明梳理当前实现的完整工作流、代码位置、前端操作，以及本次新增的"显式时间段"能力。
> 更新日期：2026-08-04（新增训练区间 / 回测验证区间支持）

---

## 一、总体工作流

```
┌────────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ ① 构建训练集           │ → │ ② 训练并落盘         │ → │ ③ 验证模型好坏       │
│  候选池每只股票        │   │  全量样本训练 GBDT/   │   │  方式A：CV自动分时段  │
│  × 每根K线每个日期     │   │  LightGBM，joblib落盘 │   │  方式B：指定日期回测  │
│  特征=当日因子         │   │                      │   │  (本次新增)          │
│  标签=未来N日收益      │   │                      │   │                      │
└────────────────────────┘   └──────────────────────┘   └──────────────────────┘
                                                              │
        ┌─────────────────────────────────────────────────────┘
        ▼
┌────────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ ④ 人工调参             │ → │ ⑤ 复用               │ → │ ⑥ 反馈               │
│  调特征权重/阈值        │   │  打分选股 / ML回测    │   │  看验证结果→再调参    │
│  (adjustId 落盘)       │   │  主回测页 / 盯盘调度  │   │  形成闭环             │
└────────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

**关键点**：训练与验证天然分时段——数据集按 `(日期, 代码)` 排序，CV 训练折永远在前、测试折永远在后、中间留 gap 防泄漏；本次新增后，训练集与回测验证还可**显式指定起止日期**。

## 二、各环节原理与代码位置

### ① 构建训练集（`ml.build_dataset`，`backend/app/ml.py:87`）

- 对候选池每只股票拉 `hist` 天 K 线（A 股走 `adapters.fetch_kline`，期货走 `fetch_future_kline`）。
- **每个 K 线日期生成一条样本**：特征 = 当日全部技术因子（动量/均线/波动率/量价等，共 36 个），标签 = 未来 `n` 日收益率。
- 产出 `{features, target, codes, dates, feature_names}`，按 `(date, code)` 排序。
- **本次新增**：`start_date` / `end_date` 参数 → 只保留落在区间内的样本（`ml.py:179-191`），实现"用一段历史训练"。

> 手动控制训练集范围的方式：候选池（板块/行业/期货/资产类别）+ 训练起止日期。
> 注意：ML 训练特征为平台内置技术因子，用户自定义的组合/表达式因子暂不参与 ML 训练（在选股打分中可用 `uf:ID`）。

### ② 训练并落盘（`ml.train_final_model`，`ml.py:356`）

- 用**数据集内全部样本**训练最终模型（`gbdt` 或 `lightgbm`），缩尾+标准化预处理参数随模型一起落盘。
- 产物：`backend/ml_models/mlmodel_<时间戳>.joblib` + sidecar JSON，结构为 `{model, feature_names, model_type, preprocess}`。

### ③ 验证模型好坏（两种方式）

**方式 A：时序 Walk-Forward CV（评估按钮，无需填日期）**

- `purged_walk_forward_split`（`ml.py:228`）：n 折滚动切分，**训练区在前、测试区在后、中间 gap 天**——本质就是"用前一段历史训练、用后一段历史验证"。
- 每折在训练折内 fit 预处理、apply 到测试折（杜绝预处理泄漏，`ml.py:207-225`）。
- 输出：每折 IC / RankIC / 多空收益，汇总 OOS IC、OOS Sharpe（`evaluate_dataset`，`ml.py:262`）。
- 折数不足自动降级（`_find_cv_splits`，`ml.py:250`）。

**方式 B：指定日期回测（本次新增，验证用"另一段明确的历史"）**

- `ml.backtest_model` 新增 `start_date` / `end_date`（`ml.py:786`）：调仓日只落在区间内（`ml.py:890-895`）。
- 主回测页日期控件对模型回测生效；ML 页「回测起始日/结束日」对「ML回测」按钮生效。
- 典型用法：训练区间 `2020-01-01~2022-12-31` → 验证回测区间 `2023-01-01~2024-12-31`。

### ④ 人工调参（`POST /api/ml/models/{mid}/adjust`，`routers/ml.py:170`）

- 参数：`featureWeights`（特征权重覆盖）+ `threshold`（预测阈值偏移）。
- 落盘为调参配置（`adjustId`），打分/回测接口传 `adjustId` 即生效。
- 前端：机器学习页模型行「调参」按钮 → 权重/阈值 → 「保存调参配置」。
- **人工权重验证闭环**：调参 → ML 回测（传 adjustId）→ 看验证期表现 → 再调。

### ⑤ 复用与联通（模型统一 dict 结构，全链路零改动）

| 出口 | 接口 | 说明 |
|---|---|---|
| 打分选股 | `POST /api/ml/score` → `score_latest` | 对候选池最新截面算因子→模型预测分排序 |
| ML 回测 | `POST /api/ml/backtest`（或 jobs `ml-backtest`）→ `backtest_model` | 分层回测 + 验证区间 |
| 主回测页 | `POST /api/select/backtest`（`modelId` 分支）→ `backtest_model` | 主回测页日期/板块/调参共用 |
| 盯盘调度 | `POST /api/monitor/config` → `scheduler._scan_signals` → `ml.score_codes` | 模型做信号引擎 |
| 人造模型 | `POST /api/ml/models/manual` | 手动设权重的"手搓模型"，与训练模型同等可用 |
| 报告 | `POST /api/reports/backtest` / `GET /api/reports/runs` | 回测结果自动存档 + HTML/Excel/PDF |

## 三、典型操作路径（分时段训练 + 分时段验证）

**场景**：用 2021-2022 数据训练，用 2023-2024 数据验证模型好坏，再手动调参。

1. **机器学习页**：
   - 候选池/板块/资产类别选好；
   - 「训练起始日」填 `2021-01-01`、「训练结束日」填 `2022-12-31`；
   - 点「评估(CV)」→ 看该时段内 OOS IC/Sharpe（时段内再自动前段训练/后段测试）；
   - 点「训练并落盘」→ 模型仅用 2021-2022 样本训练。
2. **验证**（选其一）：
   - ML 页「回测起始日」填 `2023-01-01`、「回测结束日」填 `2024-12-31` → 对模型点「ML回测」→ 看 2023-2024 验证期的净值/分组收益；
   - 或主回测页选该模型，填「回测起始日/结束日」→ 「运行回测」。
3. **调参**：模型行「调参」→ 调权重/阈值 → 「保存调参配置」→ 再「ML回测」对比验证期表现，反复迭代。
4. **复用**：满意后，模型可用于打分选股、主回测、盯盘调度。

## 五、因子库（2026-08-04 扩充：技术因子 22 → 36）

> 因子在 `backend/app/factors.py` 的 `FACTORS` 注册后，**前端因子页/选股页/ML 页自动出现**（catalog 动态加载），并自动进入 ML 训练特征集（`ml.py:112`）与人造模型权重表（`ml.py:1198`）。

**原有技术因子（22）**：5/10/20/60/120 日动量、MA5/20/60 偏离度、20/60 日波动率、RSI(6/14)、MACD、KDJ-K、WR、CCI、布林带%B、20 日振幅、量比(5)、OBV 趋势、20 日高低位置、距 52 周新高回撤。

**本次新增技术因子（14）**：

| 类别 | 因子 | 含义 | 方向 |
|---|---|---|---|
| 动量/趋势 | `momentum30` / `momentum90` | 30/90 日动量（补中长周期） | +1 |
| | `mom_accel` | 动量加速度 = 20日动量 - 10日动量（动能增强/衰减） | +1 |
| | `ema_slope20` | EMA20 斜率（趋势强度） | +1 |
| | `ma_align` | 均线排列强度：(MA5-MA20)/MA20 × (MA20-MA60)/MA60，多头为正 | +1 |
| | `bias60` | BIAS60 乖离率（超买超卖） | +1 |
| | `donchian_break20` | 唐奇安 20 日通道突破（close/20日最高-1） | +1 |
| | `dist_52w_low` | 距 52 周低点涨幅（低位反弹/深度价值） | +1 |
| 风险/波动 | `skew20` | 20 日收益偏度（右尾风险） | -1 |
| | `kurt20` | 20 日收益峰度（肥尾风险） | -1 |
| | `down_vol20` | 20 日下行波动率（只统计负收益） | -1 |
| | `max_drawdown60` | 60 日最大回撤（回撤风险） | -1 |
| 量能 | `vol_corr20` | 20 日收盘-成交量相关（量价配合度） | +1 |
| | `vol_change5` | 量能突增 = 今量/5日均量-1（放量信号） | +1 |

> 说明：
> - 快照因子（PE/PB/ROE/换手/市值/北向等 21 个）不变；`useSnapshot` 勾选后作为静态特征加入 ML 训练（含前视风险，仅探索用）。
> - 未加 250 日动量：需 250+ 根 K 线，短历史（hist=240）时会导致 ML 样本全空；可用组合因子 `momentum120 - momentum60` 近似长期反转。
> - 行业/基本面数据源字段有限，未扩展需要额外数据源的因子（股息率、PEG、市现率等，数据源不支持）。
> - 新因子均逐点版（选股/回测）+ numpy 序列版（ML/盯盘）成对实现，数值一致性由测试保障（171 个测试全过）。
