## 二、修复内容详解

### 2.1 ① 行情历史数据深度不足

**根因**：历史窗口被"前端写死/UI 封顶 → 后端默认偏短 → 适配器单次回源硬封顶"三层压死，长历史根本拉不到。

**修复**（三层全部放开）：

| 层 | 位置 | 修改前 | 修改后 |
|---|---|---|---|
| 行情页写死 | `QuoteView.vue:44` | `/kline` 固定 `days: 90`（≈4 个月） | `days: 500` |
| UI 上限 | `BacktestView.vue:301` | `max="360"`（≈1.5 年） | `max="2500"` |
| UI 上限 | `FactorRegressionView.vue:103` | `max="360"` | `max="2500"` |
| UI 上限 | `RegressionView.vue:125` | `max="300"` | `max="2500"` |
| 后端默认 | `quote.py:28` | `days: int = 150` | `days: int = 500` |
| 后端默认 | `selection.py:107` | `hist: int = 260` | `hist: int = 500` |
| 前端默认 | `MLView.vue:16` | `hist = ref(240)` | `hist = ref(500)` |
| 适配器封顶 | `adapters.py` 新浪日K | `datalen={max(1, min(days, 1023))}` | `datalen={max(1, days)}` |
| 适配器封顶 | `adapters.py` 东财日K | `lmt={max(1, min(days, 500))}` | `lmt={max(1, days)}` |

**说明**：长历史依赖既有三级缓存（内存 L1 → SQLite 磁盘 L2 → 网络）。回源数据持续累计落盘（`db.upsert_kline`），
同一代码多次查询不同窗口会自动补齐，无需一次性拉满。

### 2.2 ② 频繁 timeout / 运行缓慢

#### (1) P0 根因：HTTP 连接不复用 → 共享连接池

`adapters.py` 原 `_http_get` **每次调用都新建 `httpx.AsyncClient`**（重试循环内最多新建 3 个），
选股/回测/ML 对成百上千只股票各发一次 K 线请求，TCP/TLS 握手开销被成倍放大。

修复（`adapters.py:27-67`）：
- 新增模块级共享客户端注册表 `_http_clients`，**按 event loop id 隔离**（httpx 客户端绑定创建时的 loop；
  `optimize.py` 用独立临时 loop 跑回测，不能跨 loop 共享）；
- `_http_get` 只复用共享 client，`headers`/`timeout` 改为按请求传入；
- 新增 `close_http_client()`：应用关停（`main.py` shutdown 钩子）与 optimize 临时 loop 结束时显式关闭，防连接泄漏；
- 单笔默认超时 10s→8s、`_eastmoney_clist` 15s→10s、新浪分页页请求 10s，失败快速退出。

#### (2) P0 前端 60s 超时 → 放宽至 5 分钟

`client.js:9` 默认 `timeout: 60000`，大池选股/回测/ML 训练常跑不完被误判失败。
统一放宽到 `300000`（5 分钟），与既有 `longTask` 对齐；网络级错误仍保留 toast + 重试按钮。

#### (3) P1 K 线并发上限偏低 → 随池大小自适应

原 `asyncio.Semaphore(15)` 固定并发，500/1000/3000 大池下需 30+/67+/200+ 批拉取。
全部改为 `asyncio.Semaphore(min(50, max(15, len(codes))))`（小池不低于 15、大池不超过 50，避免打爆第三方接口）：

| 文件 | 位置 | 场景 |
|---|---|---|
| `routers/selection.py` | 107-111 | 选股技术因子 K 线 |
| `routers/selection.py` | 421 | 分层回测 K 线 |
| `routers/selection.py` | 656 | 事件驱动回测 K 线 |
| `routers/selection.py` | 764 | 因子回归回测 K 线 |
| `ml.py` | 753 | ML 打分（score_latest） |
| `ml.py` | 845 | ML 回测（backtest_model） |
| `ml.py` | 1100 | 盯盘模型打分（score_codes） |
| `routers/portfolio_opt.py` | 113 | 组合优化协方差估计 |
| `routers/risk.py` | 27 | 风险归因 |

#### (4) P2 板块/候选池构建偏慢 → 分页并发 + 缓存

- `_fetch_sina_market` 分页并发 `batch_size` 5→10（`adapters.py:395`）；
- `MARKET_CACHE_TTL` 60s→300s（`adapters.py:205`），行情页高频重复拉取不再穿透；
- 空结果不缓存逻辑保留（故障不被放大）。

#### (5) P2 匿名限流易撞 429 → 限额放宽 + 桶清理

- 匿名限流 60→**300 次/分钟**，登录用户 600→**2000 次/分钟**（`main.py:42-43`，环境变量 `QUANT_RATE_ANON`/`QUANT_RATE_USER` 可覆盖）；
- 限流桶超过 10000 个时自动清理过期桶，防长期运行内存膨胀（`main.py:66-72`）。

#### (6) optimize 临时 loop 配套

`optimize.py` 在 3 处 `asyncio.new_event_loop()` 使用后、`loop.close()` 前增加
`loop.run_until_complete(adapters.close_http_client())`，保证临时 loop 上的共享 client 正确关闭、
不污染主 loop、不产生未关闭连接告警。

3. **盯盘调度 4 条 bug**：属第一批问题清单，本次未涉及。
4. **前端长任务路径统一**：`longTask` 与默认超时现已同为 5 分钟，但部分下载接口（`downloadGet` 120s）仍偏短，
