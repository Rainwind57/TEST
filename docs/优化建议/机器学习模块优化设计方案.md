## 1. U1 — 数据窗口语义对齐（核心，P0）

### 1.1 问题机理
- 回测抓 K 线：`ml.py:1125` → `kline(code, hist + n + 25)`，窗口**永远结束于今天**。
- 时间段只在已抓窗口内过滤调仓日：`ml.py:1213-1216`（`if start_date and date_t < start_date: continue`）。
- 抓取上限：`adapters.py:596` 腾讯 `fqkline` `param={code},day,,,{days},qfq`，单请求返回条数约 **1024 条上限**。`hist=1400` 实际只拿 ≈1024 交易日（≈4 年），且锚定今天。
- 结果：所选时间段落在"今天−实际窗口"之前 → 0 个调仓日 → 空结果。

### 1.2 设计：以"终止日 + 历史长度"定义窗口
新增数据层函数，让抓取窗口**跟随 `end_date` 而非今天**，并分页突破上限：

```python
# adapters.py 新增
TENCENT_CAP = 1024          # 单请求上限
EM_CAP = 8000               # 东财上限（宽松，统一按分页处理）

async def fetch_kline_window(code: str, end_date: str, total_days: int,
                             fq: str = "qfq") -> list[dict]:
    """抓取 [end_date - total_days, end_date] 窗口的日K，自动分页突破单请求上限。"""
    start = _shift_trading_days(end_date, -total_days)   # 交易日回推，非自然日
    if total_days <= TENCENT_CAP:
        return await _fetch_tencent_bounded(code, start, end_date, total_days, fq)
    # 分页：把 [start, end] 切成 ≤CAP 的子窗口，分别抓取后按 date 去重合并
    chunks = _split_window(start, end_date, TENCENT_CAP)
    out = []
    seen = set()
    for cs, ce in chunks:
        part = await _fetch_tencent_bounded(code, cs, ce, TENCENT_CAP, fq)
        for row in part:
            if row["date"] not in seen:
                seen.add(row["date"]); out.append(row)
    return sorted(out, key=lambda r: r["date"])
```

调用侧改造（`ml.py` 训练侧 `:199` 附近、回测侧 `:1125`）：

```python
# 原：kline = await _kline_retry(kline_fn, code, hist + n + 25)
# 改：有 end_date 时锚定终止日
win_end = end_date or _today_iso()
kline = await adapters.fetch_kline_window(code, win_end, hist + n + 25)
```

### 1.3 前端联动与校验（`MLView.vue`）
- 用户选定回测时间段后，自动回填建议 `hist = 交易日(end) − 交易日(start) + n + 25` 的 1.1 倍，并禁用"小于窗口长度"的提交。
- 越界时给出明确报错而非静默空结果：`ml.py` 在 `ic_series` 为空时返回结构化错误（与 2.2 统一，`ml.py:1563-1576`）：
  ```python
  return {"ok": False, "reason": "NO_VALID_REBALANCE",
          "error": f"回测区间 [{start_date},{end_date}] 无有效调仓日："
                   f"历史长度 {hist} 天仅覆盖至 {actual_start}，请增大历史长度或后移终止日。",
          "hint": "时间段与历史长度不匹配，请参考本表调整",
          "requested": {"start": start_date, "end": end_date, "hist": hist},
          "actualWindow": actual_start_end}
  ```
  > 注：早期草稿此处写 `raise ValueError`，后与 2.2 的"结构化返回"方案统一，最终实现采用返回 `{ok:False,...}` 而非抛异常（路由层 `selection.py:418` 再转 `ValueError` 以便 HTTP 422 回传）。

### 1.4 验收
- 设 `hist=1400` 且回测 2020-2023 → 实际抓到 ≈1400 日 K 线，调仓日 > 0。
- 设 `end_date=2021-01-01`、`hist=250` → K 线窗口为 2020-01 至 2021-01（不再含今天之后）。

## 3. U3 — 持仓/调仓过程可视化增强（P1）

### 3.1 现状（已核实，非 bug）
`reporting.py:394-418` 已实现持仓图：多头/空头持仓数（折线）+ 换手股数（柱），且 `positionLedger` 在 `ml.py:1311-1317` **确有填充**（每调仓日记录 long/short 代码列表）。图仅在 `positionLedger` 为空时隐藏——空源于 U1。

### 3.2 增强方向
1. **丰富语义**：`position_ledger` 每条增加 `longCount/shortCount/turnover`，并由后端直接计算（避免前端每次重算）；报告图增"多头占比"面积。
2. **调仓明细表**：新增 `reporting.py` 区块，列出每个调仓日「新进/退出」标的（对比上一调仓日集合差），让"调仓过程"可逐期追溯。
3. **边缘保底**：当某调仓日仅有一侧分组（如只有多头无空头）时，仍记录该日持仓，避免图断裂。
4. **前端**：`MLView.vue` 报告区增加"持仓变动" Tab，默认展开（不再依赖用户触发）。

## 4. M5 — 克隆/调参模型权重自动生效（P1）

### 4.1 问题
`clone_model_with_adjust`（或"另存为新模型"）生成新模型文件，但推理 `score_latest`/`score_codes`（`ml.py:1026/1498`）只在**显式传入 `adjust`** 时才套用 `featureWeights/threshold`；新模型自身侧车未写入权重 → 用户以为"保存了新模型"，实际打分还是原模型。

### 4.2 设计
- **侧车自洽**：`clone_model_with_adjust` 将 `featureWeights`、`threshold` 写入新模型 meta（`ml.py:767/793` 的字段白名单已含 `featureWeights/threshold`，仅需确保写入）。
- **推理默认带权重**：`score_latest`/`score_codes` 在无显式 `adjust` 时，自动读取模型 meta 的 `featureWeights/threshold` 作为默认 `adjust`：
  ```python
  if adjust is None:
      meta = load_model_meta(model_id)
      if meta.get("featureWeights") or meta.get("threshold"):
          adjust = {"featureNames": meta["featureNames"],
                    "featureWeights": meta.get("featureWeights", {}),
                    "threshold": meta.get("threshold")}
  ```
- 前端 `MLView.vue:227` 已支持 `payload.adjust`，保持；新增"应用本模型自带权重"开关（默认开）。

### 4.3 验收
- 调参另存为新模型 → 直接在选股/盯盘用该模型 → 打分结果与调参后一致（无需手动再传权重）。

## 5. M6 — 信号阈值可配 + 离散调仓规则（P1）

### 5.1 现状（已核实）
- 盯盘模型模式分位阈值**硬编码**：`scheduler.py:336-341`（`pct≥0.75→看多`、`≤0.25→看空`）、`:366-371` 同逻辑。
- 回测无离散买卖规则；手动模型"规则说明"（`MLView.vue:503`）仅为文本。

### 5.2 设计 A：阈值参数化（低风险，先落地）
- 盯盘配置 `signalConfig` 增加 `bullPct`（默认 0.75）、`bearPct`（默认 0.25），`get_signal_config()` 读取并注入 `_scan_signals_impl`。
- `scheduler.py:336-341/366-371` 改用 `cfg["bullPct"]/cfg["bearPct"]`。
- 前端 `MonitorView.vue` 在"信号引擎=ML模型"下新增两个数字输入（看多/看空分位）。

### 5.3 设计 B：离散调仓规则引擎（中等风险，第二阶段）
- 模型支持可选 `ruleExpr`（受限表达式），在打分后判定买卖：
  - 安全求值：用 `ast` 白名单解析，仅允许变量 `scorePct`、`rsi`、`momentum`、`vol` 及 `+ - * / > < >= <= and or ( )` 常量。
  - 例：`scorePct >= 0.8 and rsi < 30` → 看多；`scorePct <= 0.2` → 看空/平仓。
- 回测同样支持：用 `ruleExpr` 替代单纯分组，输出明确的"买入/卖出/持有"信号序列，驱动物理持仓（而非仅多空分组收益）。
- 手动模型 `MLView.vue:503` 的"规则说明"升级为可填 `ruleExpr`，后端校验语法后落盘；非规则模型则该字段仅作备注。

### 5.4 验收
- 盯盘调 bullPct=0.9 → 仅极强势股出看多；调 bearPct=0.1 → 更多股出看空。
- 配置 `ruleExpr="scorePct>=0.8"` → 回测输出离散买卖信号，且报告"调仓明细表"可逐期查看。
