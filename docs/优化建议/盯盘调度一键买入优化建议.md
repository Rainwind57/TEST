# 盯盘调度「一键买入」优化建议（持仓分配 / 做多做空筛选 / 信号分离）

> 日期：2026-08-13 ｜ 依据：对 `backend/app/scheduler.py`（`_scan_signals_impl` / `_execute_auto_trade`）、`backend/app/routers/monitor.py`、`frontend/src/views/MonitorView.vue` 的逐行复核（非记忆）。
> 目标：让盯盘的一键买入"分配可理解、多空可筛选、信号不混叠"。

---

## 1. 优化建议

### P0 — 信号结构化（治本，去掉中文串匹配）
在 `_scan_signals_impl` 生成每条信号时，附加结构化字段，前后端统一消费：

```python
signals.append({
    "code": c, "name": ..., "score": ...,
    "signal": "看多",                 # 保留中文标签仅用于展示
    "direction": "long",              # long | short | neutral
    "action": "buy",                  # buy | sell | hold | swap
    "reason": "动量>0.1 且 RSI<30",    # 可读原因，替代模糊标签
    "swapTo": best_code or None,
})
```
- `direction`：`看多/超卖/突破` → `long`；`看空/超买/走弱` → `short`；其余 `neutral`。
- `action`：`看多`且未持仓 → `buy`；`平仓` → `sell`（全平）；`减仓` → `sell`（半平）；`中性`持仓 → `hold`；有 `swapTo` → `swap`。
- 此后前端 `signalClass/signalStyle/signalStats/batchBuy` 全部改读 `direction/action`，删除 `includes('看多')` 等脆弱判断。

### P0 — 透明化持仓分配（替代硬编码 100 股 & 不可见等权）
新增统一**分配引擎**，前端所有买入入口（单买/批量/换仓/自动调仓）共用，且下单前可预览：

```python
def plan_allocations(buy_codes: list[str], cash: float,
                     policy: dict) -> list[dict]:
    """policy: {mode:'equal'|'fixed'|'risk', perPositionPct:0.2, maxPositions:5}"""
    n = min(len(buy_codes), policy["maxPositions"])
    if n == 0: return []
    budget = cash * policy["perPositionPct"]          # 单标上限（如 20%）
    per = min(budget, cash / n)                        # 等权：取较小者
    out = []
    for code in buy_codes[:n]:
        qty = int(per / price_of(code)) // 100 * 100
        out.append({"code": code, "plannedQty": qty,
                    "plannedAmount": qty*price, "plannedPct": qty*price/cash})
    return out
```
- 前端 `buySignal`/`batchBuy`/`swapToSignal` 改为调用该引擎（先取价再算股数），删除魔数 `100`。
- 新增**分配预览面板**：扫描后展示"将买入 N 只 · 每只约 X% 仓位 · 预计占用现金 Y% · 单标上限 Z%"，让用户"理解"分配。
- 自动调仓 `_execute_auto_trade` 改为**迭代重算**：每下一单后按剩余现金更新预算（:562 改为循环内 `per = min(cash_left*0.2, cash_left/remaining)`），避免末单因现金不足被静默跳过。

### P1 — 做多 / 做空分离与筛选
- **后端**：返回信号时按 `direction` 分组（或在 `status` 接口返回 `longCandidates / shortCandidates / positionAdjust` 三类）；新增配置 `tradeDirections: "long" | "short" | "both"`，自动调仓只处理被选中的方向。
- **真正做空支持（二选一）**：
  - 方案 A（推荐，模拟可玩）：portfolio 支持 `side="short"` 融券空单，记录负持仓（或独立的 `short_positions` 表），平仓时回补；`place_order` 增加空头路径。这样 `看空` 候选才能真下单。
  - 方案 B（低成本）：若暂不接融券，则 `看空` 候选明确标记为"做空观察（需开通融券）"，在 UI 单独成列、不静默丢弃，待接入。
- **前端**：信号区加 Tab/筛选「做多候选 / 做空候选 / 持仓调整」；做多候选有"批量买入"，做空候选有"批量做空"（方案 A 下可用）。当前 `batchBuy`（:186-197）只吃 `看多`，改为读 `direction=="long"`。

### P2 — 配置与可读性
- 信号引擎配置面板增加「分配策略」（等权/固定金额/风险预算）、「单标仓位上限 %」、「最大持仓数」、「交易方向（多/空/两者）」。
- 每条信号展示 `reason`（如"动量 0.12 且 RSI 28"）替代模糊的"突破(看多)"。

```vue
<!-- 分配预览（扫描后展示） -->
<div class="alloc-preview" v-if="allocPlan">
  将买入 {{ allocPlan.count }} 只 · 每只约 {{ allocPlan.perPct }}% 仓位 · 占用现金 {{ allocPlan.usedPct }}%
</div>

<button class="btn-primary" @click="batchBuy('long')">做多信号批量买入</button>
<button class="btn-primary" v-if="shortEnabled" @click="batchBuy('short')">做空信号批量下单</button>
```

```js
const longList = computed(() => signals.value.filter(s => s.direction === 'long' && s.action === 'buy'))
const shortList = computed(() => signals.value.filter(s => s.direction === 'short' && s.action === 'sell'))

async function batchBuy(dir) {
  const list = dir === 'long' ? longList.value : shortList.value
  if (!list.length) { toast('无可用信号'); return }
  // 先取价，用分配引擎算股数，替代硬编码 100
  const plan = await api.post('/monitor/alloc-preview', { codes: list.map(s=>s.code) })
  let ok = 0
  for (const p of plan.allocations) {
    await api.post('/portfolio/order', { code: p.code,
      side: dir === 'long' ? 'buy' : 'short', qty: p.plannedQty })
    ok++
  }
  toast(`已批量下单：${ok}/${list.length}`)
}
```
