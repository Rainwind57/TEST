二、六大改进方向（逐条落地方案）

2.1 模型添加与记忆

当前"模型"= 硬编码在 factors.py 的 FACTORS 字典，用户既不能新增因子，也无法保存一套策略配置反复调用——这是与成熟平台最大的体验代差。

建议落地点

  • 策略/模型工作台（持久化）：新增 DB 表 saved_strategies（name、factor_specs JSON、filters、topN、rebalance_freq、date_range、created_at）。用户在「选股 / 回测」页配置好一套方案后可命名保存，下次一键重跑。
  • 用户自定义因子：新增 user_factors 表（name、formula 或 组合定义、params）。提供两类入口：① 组合式（对已有因子加权/运算）；② 表达式式（安全沙箱 eval，如对 close 序列的 ta 指标）。需做语法白名单防注入。
  • 回测运行档案：backtest_runs 表（config + 关键指标 + 输出 JSON 摘要），形成"研究历史"，支持横向对比。
  • 记忆/参数复用：调参寻优结果（2.4）与最佳配置回写策略表，做到"寻优 → 沉淀 → 一键加载"。
落地成本：低（纯后端 + 少量前端表单 + SQLite）。优先级：高——直接补齐"可复用的研究闭环"。

2.2 运行时间优化

瓶颈定位：run_backtest / run_factor_regression 对候选池每只股票逐个 fetch_kline（并发 15），无磁盘缓存，每次都走网络；因子计算又是逐元素 Python 循环。实测：候选池 60 只 × 历史 180 日，单次回测即触发数十次 HTTP 请求，且重启服务后缓存清零。

建议落地点

  • 磁盘级 K 线缓存：将 K 线落盘到 SQLite/Parquet，按 (code, 末日) 增量更新——仅补抓新交易日，减少 90%+ 重复请求。adapters.py:258
  • 向量化计算：引入 numpy/pandas，用 rolling/ewm 重写 MA/RSI/MACD/波动率（当前 factors.py 全是 Python for-loop），单因子计算提速 1–2 个数量级。
  • 连接池 + 批量抓取：复用 httpx.AsyncClient 连接池、提高并发上限，并按"同一交易日"批量取数。
  • 异步任务化：长回测改为「提交 → 返回 job_id → 轮询/WebSocket 推送」，避免前端 15s 超时（client.js:5）。
  • 截面预计算：每次回测只抓一次全市场快照，因子分位统一计算，避免 per-factor 重复拉取。
落地成本：中（需加依赖 + 改取数架构）。优先级：高——决定能否支撑更大候选池与日频自动化。

2.3 加入机器学习

现有回归均为线性/稳健线性（REGRESSION_METHODS）。要捕捉因子间的非线性与交互，需引入树模型与正规 ML 流程。

建议落地点

  • 模型库：新增 ml/ 模块，集成 scikit-learn + lightgbm/xgboost（GBDT 对表格数据最稳）；可选 PyTorch 做 K 线序列（CNN/LSTM）建模。
  • 防泄漏的流程：① 目标 = 未来 N 日收益（closes[i+n]/closes[i]-1，已有范式）；② 仅用 t-1 及之前信息；③ 时序交叉验证（Purged Walk-Forward / K-fold by time），严禁随机 shuffle。
  • 特征与目标工程：复用现有 32 个因子作特征；加缺失/异常值处理（winsorize）、标准化。
  • 评估与可解释：输出样本外 IC、RankIC、Sharpe、特征重要性、学习曲线；给出"训练/验证/测试"三段指标，防止过拟合自夸。
  • 模型版本化：训练产物用 joblib 落盘 + 元数据（训练区间、特征集、指标），与 2.1 的策略表联动。
  • 新页面：/ml ——选特征/目标/模型/训练，可视化特征重要性与 OOS 净值。
新增依赖：numpy pandas scikit-learn lightgbm。落地成本：中。优先级：中高——显著提升预测力，但务必配套严谨的 OOS 评估。

2.4 自动模拟盯盘调参

当前模拟盘净值只在手动下单瞬间记录（portfolio.py:133），无调度、无信号、无寻优。对标"智能条件单 / 自动再平衡 / 参数寻优"需补齐三块。

建议落地点

  • 定时盯盘调度器：用 APScheduler 或 asyncio 后台循环，交易日下午收盘后自动：重算 watchlist/universe 因子打分 → 生成买卖信号（突破/跌破阈值、换仓）→ 可选自动调仓（按已存策略）。
  • 日频净值记录：调度器每日按收盘价刷新持仓市值并写 equity_history，净值曲线才完整（当前只在交易时有点）。
  • 参数寻优：引入 optuna 做贝叶斯搜索，对窗口长度、权重、持有期 N、分组数、阈值做多目标优化（最大化 Sharpe / IC，约束换手率）。结果回写策略表（2.1）。
  • Walk-Forward 寻优：滚动窗口训练+验证，避免"全样本调参 → 过拟合"陷阱。
  • 盯盘看板 + 预警：前端新增 /monitor 页，实时 PnL、回撤告警、信号流；用轮询或 WebSocket 推送阈值触发提醒（price/drawdown/因子信号）。
注意：自动调仓涉及"模拟盘"边界，必须默认关闭、需用户显式开启，并明确标注"模拟、非实盘"。
落地成本：中高。优先级：中——属于"智能化"亮点，建议放在 v2 中期。

2.5 输出回测报告

当前回测仅返回 JSON、前端画三张图，无下载、无完整绩效指标、无基准对比、无交易成本。

建议落地点

  • 完整绩效指标：在 run_backtest 后端计算并下钻——累计/年化收益、年化波动、Sharpe、Sortino、最大回撤、Calmar、信息比率 IR、换手率、胜率，以及对多空组合与最高组分分别统计。
  • 交易成本模型：加入佣金（如万 2.5）、印花税（卖出千 1）、滑点/冲击成本参数（selection.py:201 调仓处扣减），让回测贴近真实。
  • 基准对比：叠加沪深300/中证500 作为 benchmark，输出 Alpha/Beta、相对强弱。
  • 多格式导出：一键生成 ① HTML（ECharts 快照+指标卡，即本建议书同款风格）；② Excel（逐期 IC、分组收益、成交明细，可用本项目已配置的 minimax-xlsx）；③ PDF 研报（minimax-pdf）。
  • 报告存档：与 2.1 的 backtest_runs 关联，历史报告可追溯。
落地成本：中（指标计算 + 导出脚手架，导出可复用已配置的 quant 交付技能）。优先级：高——直接产出"可交付的研究成果"。

四、风险与注意事项

  • 前视偏差（Look-ahead）：所有因子/特征必须严格只用 t-1 及之前信息；回归目标必须是"未来"收益。新增 ML 模块时尤需警惕。
  • 幸存者偏差：当前候选池取自"当下全市场快照"，已退市股票不在内，会系统性高估历史收益。回测应支持含退市样本的数据源。
  • 过拟合：参数寻优（2.4）务必用 Walk-Forward / 时序 CV，禁止在全样本上调参后宣称高收益；报告须披露样本内/外指标。
  • 数据合规：第三方行情接口（腾讯/新浪/东财）有使用条款，规模化商用需评估授权；建议对关键数据接入本项目已验证的 neodata / westock-data 正规源。
  • 模拟边界：自动调仓/盯盘仅限模拟盘，必须默认关闭并明确标注，杜绝与实盘混淆。
