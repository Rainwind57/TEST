## 一、回测报告内容缺口（用户反馈①）

### 1.1 回测时间段信息完全缺失（确认）
`backend/app/reporting.py` 的 `render_html`（38-164 行）与 `render_pdf`（217-312 行）：
- 报告载荷 `payload` 里**包含 `config`**（含 `startDate`/`endDate`/`hist`，见 `payload_from_result` 25-35 行），但 `render_html` **从不渲染 `config`**——仅展示 `factorLabel`、KPI、基准、分组、IC 统计、三张图。
- 报告里**没有"回测区间：YYYY-MM-DD ~ YYYY-MM-DD"这一行**。用户事后拿到报告，无法一眼看出这次回测覆盖哪段时间，尤其当 `startDate/endDate` 与 `hist` 语义不一致时（见第二章），报告还"假装"覆盖全 `hist`，误导更强。

### 1.2 "模型是什么"标注不清晰（确认，部分满足）
- ML 回测：后端 `selection.py:385` 生成 `factorLabel = f"ML回测-{body.modelId}"`，**模型 ID 进了报告标题**（render_html 标题 = factorLabel）。
- 因子回测：标题是因子名（如"20日动量"），**未标注这是"因子"还是"模型"**。
- **问题**：① 报告里没有独立的"策略来源（技术因子 / ML 模型）"字段；② 模型回测只显示 ID（如 `mlmodel_20260803_164048`），不显示模型类型/超参/训练区间，可读性差；③ 配置里的 `modelId`/`factor` 在 `config` 中但未被报告渲染。

### 1.3 图表：HTML 有、PDF 没有（确认）
- HTML 报告含 3 张 ECharts 图：多空累计收益与回撤、分组平均收益、IC/RankIC 时序（render_html 125-162 行）。
- **但 PDF 报告（render_pdf）纯文字 KPI，无任何图**（217-312 行仅 `drawString`）。用户导出 PDF 时看不到走势图。
- 另：HTML 报告的图依赖 `cdn.jsdelivr.net`（reporting.py:101），国内常打不开（详见《_图表与报告.md》2.1）——即"图表会更好"在离线环境也未必见效。

### 1.4 建议（报告应补齐的信息块）
报告头部增加一块"回测概要"，渲染自 `config`：
`策略来源`(技术因子/ML模型) · `模型或因子名`(含超参/训练区间) · `回测区间`(startDate~endDate) · `历史长度`(hist) · `基准` · `成本`(佣金/印花税/滑点) · `分组数/持有天数/候选池`。
PDF 用 matplotlib 生成净值/回撤/分组图嵌入。

## 二、回测起止日 × 历史长度 逻辑矛盾（用户反馈②，核心 Bug）

### 2.1 现象
在回测页（BacktestView）设定"回测起始日 / 回测结束日"后，**"历史长度(hist)"输入框不会随之变化，也没有任何提示**；用户期望：选了起止日，系统应自动算出需要多长历史（因子计算前置窗口）。实际：两者各算各的，结果常常"看起来选了一整段，跑出来的却是另一段"。

### 2.2 根因（代码实证）
**前端（两个输入框互不联动）：**
- `BacktestView.vue:34` `hist = ref(180)`；`:301` `<input v-model="hist" ... min="60" max="2500">`（历史长度）。
- `BacktestView.vue:41-42` `startDate/endDate = ref('')`；`:302-303` 两个 `type="date"` 输入框。
- **没有任何 `watch(startDate/endDate)` 去反推 `hist`**，也没有把二者一起校验。提交时 `backtestConfig()`（93-110 行）原样把 `hist` 与 `startDate/endDate` 一并发给后端。

**后端（取数窗口与日期过滤脱节）：**
- `selection.py:398` `hist = max(60, body.hist)` → 决定 K 线取数长度。
- `selection.py:429` `kline = await adapters.fetch_kline(code, hist)` → **取的是"最近 hist 天"（截止到最新交易日），不是 `[endDate-hist, endDate]`**。
- `selection.py:478-481` `if body.startDate and date_t < body.startDate: continue` / `if body.endDate and date_t > body.endDate: continue` → **`startDate/endDate` 只过滤"调仓日"，不参与取数窗口**。
- 调仓循环的数据源 `ref_dates` 来自所拉 K 线（`:450`），即被 `hist` 截断；每个调仓还需 `i>=20`（`:485`）。

### 2.3 三种具体矛盾场景
1. **startDate 被 hist 静默覆盖**：选 `startDate=2020-01-01`，但 `hist=180` 只取最近 180 天（约到今天）。`startDate` 之前的调仓本就不在数据里，过滤后又把 `[今天-180, startDate]` 这段也剔掉 → **实际回测起点 ≈ 今天-180，用户选的 startDate 形同虚设**，且报告还按 hist 显示"全程"，形成"选了日期却没跑那段"的矛盾。
2. **endDate 在过去 + 默认 hist → 空结果/报错**：选 `endDate=2024-12-31` 而 `hist=180`、最新交易日是 2026-08，所取数据全在 endDate 之后，`:480` 过滤后**无任何调仓日** → 触发 `:437` "有效股票样本不足"或返回空，用户一脸困惑（明明选了区间却没结果）。
3. **语义重叠却双输入**：`hist`（窗口长度）与 `startDate`（窗口起点）在概念上共同定义"数据覆盖区间"，却被拆成两个独立框、无一致性约束，用户很难意识到二者要配合。

### 2.4 建议修复方向（供后续补丁参考）
- **前端联动**：`watch([startDate, endDate])` → 自动推导 `hist = max(60, (endDate - startDate 的天数) + 暖机缓冲(如 60~120))` 并回填；起止日变化时同步刷新 `hist` 输入框与提示。
- **后端取数对齐日期**：当 `startDate` 给定时，K 线取数起点应为 `startDate - 暖机缓冲`，终点为 `endDate`（或最新），而非"最近 hist 天"；`hist` 退化为"暖机缓冲天数"。
- **一致性校验与提示**：`endDate < startDate`、或 `hist` 不足以覆盖 `startDate` 前置窗口时，前端/后端给出明确报错而非静默跑空。

## 四、与既有清单的关联
- **数据深度（第二篇）** × **本章 bug**：若按建议改为"按 startDate 取数"，会真正去拉 `startDate` 之前多年的 K 线，正好撞上第二篇指出的"适配器封顶 1023 天 / 行情只 90 天"——不先解决数据深度，长区间回测仍会被静默截断。
- **报告图表（第三篇 2.1）** × **本章 1.3**：PDF 无图、HTML 图依赖 CDN，是同一报告的两条独立短板，建议一并修。
- **模块共享（第一篇③）**：报告里"模型/因子"信息若结构化（策略来源 + 模型 ID + 训练区间），正好可以作为"模型跨模块共享"的元数据基础。
