# 应用残留项说明：手动调参初始权重值

> 日期：2026-08-18
> 性质：非缺陷（体验级残留），不影响功能、不导致崩溃
> 范围：机器学习模块 · 模型调参（手动调整特征权重）界面

---

## 一、现象描述

在机器学习模块的「模型调参」界面中，对每个特征权重进行人工调整时，**权重输入框的默认初始值被统一显示为 `1.0`**，不论该特征在原始模型中的实际重要度高低，均以 1.0 作为起点。

用户看到的表现是：打开调参面板后，所有特征后面跟着的权重数字都是 1，而非按模型已学到的权重分布预填；如果直接在该状态下点「评分 / 应用」，相当于把所有特征权重拉平为 1 再参与计算。

---

## 二、当前处理原则（为何判定为非缺陷）

调参界面在拉不到"该模型已有权重"或"用户上一次保存的权重"时，用 `1.0` 作为兜底默认值。这个做法对**树模型类**（如随机森林、XGBoost、LightGBM 等）是合理的：

- 树模型的"权重"更多是调参者主观设定的偏好强度，1.0 表示"等权/中性"，语义清楚；
- 调参本就是人工干预，起点拉平反而便于逐项上调/下调做对比实验；
- 界面已对该默认值做了文字提示，引导用户按需修改，不会让人误以为是"模型真实权重"。

因此该现象**不是 bug**，也不会导致任何计算错误或信号缺失。

---

## 三、可能影响（仅在个别场景）

仅当模型本身是**线性类**（如线性回归、逻辑回归、线性 SVM）时，1.0 作为统一起点才略显粗糙：

- 线性模型的系数本身有量纲与量级差异，统一 1.0 起点意味着丢失了模型已学到的系数相对大小；
- 此时用户若直接应用，等于用"等权线性组合"覆盖了原本带系数的模型，结果会有偏差。

但即便如此，也只是"调参起点不够聪明"，用户手动改回即可，不产生错误数据或崩溃。

---

## 四、可选改进方向（锦上添花，非必须）

如希望体验更顺手，可考虑以下任一最小改动（均不触碰核心计算）：

1. **预填已有权重**：调参面板打开时，优先读取该模型 meta 中已存储的特征权重作为初始值；仅在确实缺失时才回落到 1.0。
2. **线性模型智能默认**：若模型类型为线性类，初始权重改用模型系数的归一化值（按绝对值缩放，使最大项≈1），而非统一 1.0；树模型仍保持 1.0 中性默认。
3. **UI 提示强化**：在权重输入框旁标注"（默认 1.0 = 等权，请按需调整）"，降低误解。

### 落地状态（2026-08-18）

| 方向 | 状态 | 实现 |
|------|------|------|
| 1 预填已有权重 | ✅ 已有 | `MLView.vue` `openAdjust` 读取 `meta.featureWeights` 回显 |
| 2 线性模型智能默认 | ✅ 本次补齐 | `manual`（人工线性）模型未设置权重的因子默认 0（不参与），与模型「未设置=0」语义一致；树模型仍 1.0 |
| 3 UI 提示强化 | ✅ 本次补齐 | 面板顶部提示按模型类型区分；权重输入框加 `title` 悬浮说明（树模型"默认 1.0=等权"，线性模型"可为负、未设置默认 0"） |

> 说明：线性模型（`manual`）权重允许为负（负=反向因子），本次同时放开输入框 `min="0"` 限制，仅对树模型保留非负约束。

## 六、结论

手动调参初始值 = 1.0 属于**设计取舍而非缺陷**：对树模型合理、对线性模型略粗糙但不出错。三项可选改进方向（预填已有权重 / 线性模型智能默认 / UI 提示强化）已于 2026-08-18 全部落地，本残留项关闭。
