# 应用问题清单：模拟盘持仓不支持行内买入/卖出（2026-08-17）

## 1. 现象
- 模拟盘「持仓」表格（前端 PortfolioView.vue 持仓区）每一行**只有展示列**：名称、数量、成本价、现价、市值、浮动盈亏、盈亏率，**没有任何「买入 / 卖出」操作按钮**，也没有"操作"列。
- 现有的买卖入口是一个**与持仓完全解耦的通用下单面板**（顶部独立区域）：用户必须手动输入股票代码、选择方向（买入 / 卖出）、填写数量，再点「下单」。
- 因此，要对某只**已持仓**的股票加仓或减仓，用户得先从持仓行手抄 / 记忆代码，再到上方面板重新选方向、输数量，过程繁琐且易输错。

## 2. 影响
- 持仓数量较多时，逐只手动重输代码买卖体验很差，且容易把代码 / 方向 / 数量填错（A 股需整手 100 股倍数，输错会被后端拒单）。
- 缺少对单只持仓的"快捷减仓 / 清仓"入口（后端其实已支持：卖出数量等于持仓量时自动 DELETE 该行）。
- 这是一个**功能 / 交互缺口**，不是崩溃；下单面板本身可以正常下单，只是没有"针对持仓行"的便捷联动。

## 3. 根因（前端交互缺失，后端已具备能力）
- 前端持仓表格未渲染操作列，也未绑定任何"点击持仓行预填下单"的交互逻辑。
- 后端 `/portfolio/order` 已经能够**按单只持仓股**执行买卖：
  - 买入（加仓）：若已持有多头则合并数量与成本价，否则新开仓；
  - 卖出（减仓）：会校验该代码多头持仓是否足够，数量等于持仓量时自动清仓删除该行。
- 前端 store 也已有 `portfolio.order(code, side, qty)` 方法可直接调用。
- 结论：**能力在后端 / store 早已就绪，只差前端把"持仓行"和"下单面板"联动起来**——属于纯前端 UX 缺失，无需改后端。

## 4. 修复方向（最小改动，仅前端）
建议方案（延续现有下单面板的调用方式，不引入新的后端接口）：

- **持仓表增加「操作」列**：每只股票提供「买入(加仓)」「卖出(减仓)」两个按钮。
- **点击后预填现有下单面板**（或弹层）：
  - 把 `p.code` 写入下单面板的代码框（并触发行情 / 可交易校验）；
  - 方向自动切到对应买卖；
  - 数量默认填当前持仓量 `p.qty`（卖出时即"清仓"语义；买入时可让用户改数量）。
- 复用现有 `portfolio.order(code, side, qty)` 完成下单，下单成功后面板与持仓列表会随 `fetch` 刷新。

可选增强：
- 卖出按钮额外提供「清仓」快捷项（直接传 `p.qty`）。
- 数量输入框对持仓股预填时，给出"可卖最大 / 可买最大"提示。

## 5. 关联说明
- 与「盯盘扫描崩溃」(`'sqlite3.Row' object has no attribute 'get'`) 是**相互独立**的问题：前者是数据库行被当字典访问导致的崩溃，本项是前端交互缺口，二者无因果关系。
- 本项不改变任何后端 / 业务逻辑，只补前端入口，风险低。
