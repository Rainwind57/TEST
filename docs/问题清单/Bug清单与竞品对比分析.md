## 一、核心结论（先说最重要的）

您反馈的「**跑完因子之后没办法有模型给我回测**」经代码级验证**完全属实**，且不是个别现象，而是**全平台系统性的"研究链路断裂"**：

```
数据 → 因子 ✅ → 选股 ✅ → 分层回测 ✅
                ↓
              ML 训练 ✅ → 模型落盘 ✅ → ❌ 死路（无任何接口能加载模型驱动回测/选股）
                ↓
              参数寻优 ✅ → 最优参数 → ⚠️ 只能存策略手动重跑（无一键回填）
                ↓
              组合优化 ✅ → 权重向量 → ❌ 死路（模拟盘只支持等权买入，权重被丢弃）
```

**证据链（后端）**：
- `ml.py:210-229` `train_final_model()` 把模型 `joblib.dump` 落盘后仅返回元信息；全局检索 `joblib.load` / `.predict(`——**除交叉验证内部评估外，落盘模型再无任何加载/推理调用**。
- `routers/ml.py:50-59` 模型管理接口只有 `list_models` / `delete_model`，**没有 `predict` 接口**。
- `routers/selection.py:196-199` 回测入口第一行 `if body.factor not in FACTORS: raise`——回测因子**只接受内置技术因子常量**，请求体中根本不存在 `modelId` 字段。模型分数无法作为选股信号进入回测。

**证据链（前端）**：
- `MLView.vue` 训练完成后模型列表**只有"删除"按钮**（L138），没有"用该模型回测/选股"。
- 全站 Pinia 仅共享自选股（watchlist），**没有任何研究结果共享 store**；`router/index.js` 所有跳转不带 query/params——每个页面都是信息孤岛。
- `OptimizeView.vue` 拿到最优参数后只能"保存为策略"，无法一键带参跳转回测页。
- `PortfolioOptView.vue` 的权重结果只画饼图，无"导入模拟盘"按钮；且 μ/协方差矩阵要求**用户手工粘贴文本**，与上游选股/回测结果零数据流。

这正是「很多选项都无继续的方式」的技术根因：**缺少"把 X 的结果拿去 Y"的三件套——后端衔接接口 + 前端下一步按钮 + 跨页共享状态**。

## 二、Bug 清单（按严重程度分级）

### P0 — 链路断裂（功能性死路）

| # | 位置 | 问题 | 修复建议 |
|---|------|------|----------|
| 1 | `ml.py:210` → `routers/selection.py:198` | ML 模型落盘后无任何消费方，训练完即死路 | 新增 `/api/ml/predict`（加载模型对股票池打分），并让 `run_select`/`run_backtest` 接受 `modelId`，将预测分作为因子参与打分。**这是打通用户核心痛点的最小改动** |
| 2 | `routers/portfolio_opt.py:11-41` → `routers/portfolio.py:514-561` | 组合优化输出权重向量，但模拟盘 `apply_selection` 只支持 `watchlist/buy` 且强制等权（`totalCash/len(codes)`），优化权重被完全丢弃 | `apply_selection` 增加 `action=weights`，按权重向量分配资金下单 |
| 3 | `routers/strategies.py:47-61` | `VALID_KINDS` 声明支持 `regression`，实际代码直接 400"暂不支持"，前后矛盾 | 补实现或从 VALID_KINDS 移除 |
| 4 | 前端全局 | 无研究结果共享 store、无带参跳转、无"下一步"按钮体系 | 新增 `researchStore`（当前因子/模型/最优参数/选股结果）+ 各页面添加衔接按钮 |
| 5 | `ml.py:37` | 自定义因子/基本面因子（PE/PB/换手率）无法进入 ML 特征集，`sem_factor_keys` 只取内置技术因子 | 特征构建支持 `uf:` 自定义因子与快照因子 |

### P1 — 计算结果错误（数值不可信）

| # | 位置 | 问题 | 影响 |
|---|------|------|------|
| 6 | `factors.py:505-514` | 年化收益：`years = len(period_returns)/252`，但传入的是每 n 日调仓收益，**年化被高估约 n 倍**（n=5 时严重虚高） | 回测报告年化收益不可信 |
| 7 | `factors.py:523-531` | Sharpe 用 `std×√252` 缩放 n 日收益，**高估 √n 倍** | 夏普比率虚高 |
| 8 | `ml.py:179-180` | `_bucket_returns` 返回标量却被包成 1 元素数组求 std → **oosSharpe 恒等于 0** | OOS 验证指标失效 |
| 9 | `factors.py:586` | ICIR = meanIC/stdIC×√N，N 用回测总期数而非年化期数，口径错误 | 因子评价失真 |
| 10 | `ml.py:105-124` | Walk-Forward 只对测试起点留 gap，**训练集尾部样本的标签（未来 n 日收益）仍越过 gap 泄漏进测试区**——不是真正的 purged 分割 | CV 结果乐观偏差 |
| 11 | `risk.py:60` | Barra 归因用**截面暴露的协方差** `np.cov(X)` 冒充**因子收益时序协方差**，对象根本错误；且缺市值与行业因子（A 股最主要风险源） | 风险分解结论失真 |
| 12 | `adapters.py:218-252` | 用当前上市成分做历史回测，**幸存者偏差**（已退市股不在池中） | 回测收益系统性高估 |

## 三、优化建议（按投入产出比排序）

### 第一优先级：打通研究闭环（解决"无继续方式"）

1. **ML→回测**（P0-1）：`/api/ml/predict` + 回测/选股接受 `modelId`。后端预计 ~100 行改动，前端 ML 页加"用此模型回测"按钮带参跳转。
2. **寻优→回测一键回填**：OptimizeView 增加"应用最优参数"按钮，`router.push({path:'/backtest', query: bestParams})`，回测页 onMounted 读 query 预填。
3. **组合优化→模拟盘**：优化权重一键按比例建仓；同时让 μ/cov 可以从"选股结果 + 历史协方差"自动生成，取消手工粘贴矩阵。
4. **选股→回测**：选股结果页加"对该组合发起回测"。
5. **全局 `researchStore`**：贯穿"当前研究上下文"（因子 → 模型 → 参数 → 组合），侧边栏按"数据→研究→交易"分组并显示工作流进度。

### 第二优先级：修正数值口径（让结果可信）

6. 统一年化缩放：全部乘 `√(252/n)` 或按实际交易日跨度年化（修 #6/#7/#9）。
7. 修复 oosSharpe 恒 0（#8）与真 purged 分割（#10）。
8. 引入真实成本模型：佣金双边万2.5 + 印花税卖出单边万5 + 过户费万0.1 + 滑点，模拟盘/分钟回测/多空组合统一口径。
9. 撮合约束：T+1、涨跌停（主板±10%/创业板科创板±20%/北交所±30%、ST±5%）、停牌跳过、整手取整。
10. 消除幸存者偏差：用 as-of 时点的上市股票池。

### 第三优先级：工程加固

11. SQLite 开 WAL + 连接池 + 写串行化；jobs 队列加 TTL 清理；行情缓存加 LRU 上限。
12. 寻优/ML/分钟回测全部接入 jobs 异步队列（提交→job_id→轮询→取消），前端长任务改轮询而非 60s 硬等。
13. JWT secret 强制从环境变量读取；下单改事务原子操作。
14. 前端：401 统一跳登录、路由守卫、轮询失败指数退避、结果导出（选股/ML/优化页目前均不可导出）。

### 4.3 竞品是如何解决"研究闭环"的（可直接借鉴）

**Qlib 的答案——workflow 配置贯通**：一份 YAML 里依次声明 `data handler → model → strategy(TopkDropout, 直接吃模型预测分) → backtest → analysis`，`qrun` 一条命令跑完全链路。**模型预测分数天生就是组合构建器的输入**，不存在"训练完没人消费"的问题。TEST-main 可以直接抄这个思想：让回测接口接受 `signal_source ∈ {factor, model, custom}`。

**BigQuant 的答案——画布连线**：可视化画布上"数据模块 → 特征模块 → 训练模块 → 预测模块 → 回测模块"用线连起来，每个模块的输出端口就是下一个模块的输入端口，**UI 层面根本不可能出现"死路"**。TEST-main 不必做拖拽画布，但每个结果页底部加一排"下一步"按钮（成本极低）就能达到 80% 的效果。

**聚宽的答案——代码即胶水**：策略代码里研究/训练/回测共享同一运行时，用户自己用变量传递。这条路线对 TEST-main 不适用（它是表单式 UI），更应学前两者。

### 4.4 TEST-main 的相对优势（客观说）

1. **架构现代**：FastAPI + Vue3 前后端分离、异步任务队列、三级 K 线缓存，比果仁等老平台的技术栈新。
2. **防过拟合意识**：Walk-Forward、IS/OOS、purged 分割（虽实现有瑕疵）的理念在个人项目中少见。
3. **免费自托管**：不依赖云平台配额，数据与策略完全私有——这是聚宽/BigQuant 用户的普遍痛点。
4. **模块齐全**：因子/ML/寻优/组合优化/归因/模拟盘/盯盘一应俱全，广度超过多数开源项目，缺的是"连线"而非"节点"。
