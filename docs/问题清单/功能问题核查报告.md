## 二、逐条详述

### ① 北交所股票导入 —— 部分存在（需修）
- **板块级**：`BOARD_LABELS` 含 `bse`，`SelectView.vue`/`BacktestView.vue` 板块下拉含"北交所"，`adapters.BOARD_MATCHERS["bse"]`（adapters.py:186）可用。
- **单只导入（核心缺口）**：行情页 `QuoteView.addCode` → `normalizeCode`（`frontend/src/utils/format.js:1-8`）：
  ```js
  if (raw.startsWith('6')||'5'||'9') return 'sh'+raw
  if (raw.startsWith('0')||'3')     return 'sz'+raw
  return null   // 北交所 8xxxxx / 920xxx 全部走到这里 → 报错"代码格式错误"
  ```
  北交所代码（如 `830799`、`920799`）既非 sh/sz 前缀，6 位判断也不命中 `8`/`920`，直接返回 `null`，`addCode` 提示"代码格式错误，应为 6 位数字或 sh/sz 前缀"。**单只北交所股票无法手动加入自选/行情。**
- **修复建议**：在 `normalizeCode` 增加 `8xxxxx`/`920xxx`/`bj` 前缀 → `bj` 规范化（`bj830799`）；同步修正 `QuoteView` 提示文案与 `adapters` 的腾讯 K 线前缀转换（`_to_tencent_prefix` 对 bj 用市场 `0` 是错的，需映射为北交所市场位）。

### ② 期货数据不能加入模型计算 —— 真实存在（需修）
- 期货**行情**适配器已存在：`adapters.fetch_future_quotes`（adapters.py:930-1010，中金所走新浪、商品期货走东财 ulist），可拿到实时价/涨跌/持仓。
- 但**模型计算链路完全不接期货**：`run_select`/`run_backtest`/`ml.score_latest`/`ml.backtest_model` 均通过 `adapters.fetch_market_list(board)` + `fetch_kline` 取 **A 股**数据，无任何 `fetch_future_*` 调用；`ml.py` 训练/打分特征也只来自 A 股量价/财务/资金流快照。
- 即：期货数据"拿得到"，但**进不了选股、回测、机器学习**——与用户"期货等数据不能加入模型计算"完全吻合。
- **修复建议**：① 新增期货 K 线适配器 `fetch_future_kline`；② 在 `ml.build_dataset`/`run_backtest` 增加 `assetClass: a-share|future` 分支，支持以期货序列构造特征参与训练与回测；③ 前端增加"资产类别"切换。

### ③ 因子数无添加 —— 部分存在（需修）
- **不能做的**：`factors.FACTORS` / `SNAPSHOT_FACTORS` 是硬编码字典（`/factors/catalog` 只读返回），**前端无法新增"原始新因子"**（新的量价公式、新的数据源因子都加不了）。
- **能做的**：
  - `StrategiesView.vue:61` 提供"自定义因子"创建入口：`POST /user-factors`（kind=composite，definition={factors}），即**加权组合因子**；
  - 表达式引擎 `factor_expr.py` + 选股 `expression` 参数支持自定义公式；
  - `SelectView.vue:67` 加载 `uf:{id}` 自定义因子参与打分。
- **结论**：可加"组合/表达式"因子，但**无法扩展新的基础因子库**——对应"因子数无添加"中无法新增基础因子的诉求。
- **修复建议**：在 FactorView 增加"新建因子"表单（选基础算子+参数→落 `user_factors`），或开放 `FACTORS` 注册接口，使新增因子与内置因子同等参与选股/回测/ML。

### ④ 无法进行"人造/手动模型" —— 真实存在（需修）★本次确认
> 用户反馈："还是无法进行人造模型"。经代码实测，该问题**真实存在**，此前报告误判为"已基本具备"，在此正式纠正。
- **模型只有两条来源**（backend/app/ml.py）：
  1. **自动训练** `/ml/train`：只能选 `gbdt`/`lightgbm`，结构由算法决定，**您无法选因子、设权重、写规则**；
  2. **导入外部 joblib** `/ml/models/import`：要求您自己在平台外用 sklearn/lightgbm 序列化一个含 `model + feature_names` 的包，且特征名必须与平台 `build_dataset` 完全一致——普通用户几乎不可能用起来（见 P8）。
- **"调参"不是人造模型**：`/ml/models/{mid}/adjust`（`ml.py`）只能**基于已训练出的模型**改权重/阈值，不能凭空造一个。
- **前端无入口**：`MLView.vue` 只有"训练""导入文件""调参"按钮，**没有"新建/手搓模型"表单**。
- **模型对象本质**（利好改造）：`ml.py` 中模型就是一个 `dict{model(.predict), featureNames}`（见 `ml.py:348/523/1106`）。只要人造模型也实现 `.predict(X)` 且 `featureNames` 对齐，现有的打分、回测、去主回测、甚至盯盘调度都能零改动复用。
- **修复建议（低成本，一次改动可同时解决 P4+P5）**：
  - 后端新增 `POST /api/ml/models/manual`：接收 `{name, type, featureWeights, threshold, rule}`，落盘为与现有同构的 `dict{model(wrapper.predict), featureNames}`；
  - 前端 `MLView` 加"新建人造模型"表单（选因子 + 填权重/规则）；
  - 落盘后即可在盯盘调度（P5）被选为信号引擎。

### ⑤ 模型无法用于盯盘调度 —— 真实存在（需修）
- `MonitorView.vue` 仅有"开启/停止调度"按钮，**无任何模型选择 / 信号引擎切换**。
- `backend/app/scheduler.py` 的 `_scan_signals()` 只用 `momentum` + `rsi` 两条硬编码规则生成信号，`grep` 确认其**未 import ml、无 `load_model`/`predict`**；`routers/monitor.py` 也无"选择模型"接口。
- 这正是模块间断点：ML 训练出的模型（含 P4 人造模型）无法进入盯盘调度。
- **修复建议**：给 `/api/monitor` 增加 `config`（signal_mode: rule|model、model_id、阈值）；`_scan_signals` 在 model 模式下 `ml.load_model(mid).predict(特征)` 替代规则；前端 MonitorView 增加"信号引擎"下拉 + 模型选择。

### ⑥ 日期不可自定义时间段 —— 真实存在（前端缺控件）
- **后端已支持**：
  - `SelectBody.startDate/endDate`（selection.py:97-98），`_fetch_technical_values` 在指定区间取截面（selection.py:120-129）；
  - `BacktestBody.startDate/endDate`（selection.py:351-352），回测循环按 `date_t < startDate / > endDate` 跳过（selection.py:455-458）。
- **前端未暴露**：
  - `SelectView.runSelect()` 只发送 `board/poolSize/topN/factors/filters`，**无 startDate/endDate**；
  - `BacktestView.backtestConfig()` 只发送 `board/poolSize/groups/n/hist/benchmark/...`，**无 startDate/endDate**；
  - 两个页面模板里只有"历史长度(日)/持有天数"等相对天数，**没有任何日期选择器**。
- 即：后端能力具备，但**用户在界面上完全无法设置时间段**——与用户反馈一致。
- **修复建议**：在 SelectView / BacktestView 增加 `el-date-picker` 或原生 `<input type="date">` 双控件，提交时并入 `startDate/endDate`。

### ⑦ 不支持选**行业板块**回测（如生物制药 / 医药 / 新能源 / 半导体）—— 真实存在（需修）
> 用户澄清："板块"指**行业板块**（生物制药、医药、新能源、半导体等），不是交易所板块。
- **现状：板块下拉只有交易所板块，无行业板块**：
  - 前端 `SelectView.vue:16-23` 与 `BacktestView.vue:12-19` 的 `BOARD_OPTIONS` 均为：`全部A股 / 沪市主板 / 深市主板 / 创业板 / 科创板 / 北交所`（外加沪深300/中证500/ETF 作为基准）。**没有任何"生物制药/医药/新能源/半导体"等行业入口。**
  - 后端 `adapters.BOARD_MATCHERS`（adapters.py:180-191）同样只有交易所/指数层面的匹配，**无行业键**；`fetch_market_list(board)` 对任意未知 board 会 fallback 到 "all"，因此后端也不存在"按行业取成分股"的路径。
- **行业数据其实存在，但只用于中性化，不用于选股范围**：
  - `adapters.fetch_sector_map()`（adapters.py:765-788）能拉到 **股票 → 东财行业** 映射（如 `sh600519 → 食品饮料`），并对外提供 `GET /api/data/sectors`（routers/data.py:41-47）。
  - 但该映射**仅**在 `factors.neutralized_zscore` / `sector_dummies`（factors.py:477-516）中用于"剥离行业影响"，**从未用来构造"某行业成分股池"**供选股/回测使用。
- **结论**：用户诉求（行业板块回测）当前**确实不支持**——界面无行业选项、后端无行业选股路径。
- **修复建议**：
  1. 后端 `fetch_market_list` 增加 `sector:<行业名>` 分支：调 `fetch_sector_map()` 得到 `code→行业` 映射，过滤出目标行业代码池；
  2. `BOARD_OPTIONS`（或新增 `SECTOR_OPTIONS`）从 `/api/data/sectors` 动态加载行业列表，前端下拉改为"交易所板块 + 行业板块"两级或并排；
  3. 回测/选股 `board` 参数兼容 `sector:生物制药` 透传并真正按行业过滤候选池；
  4. （顺带）`MLView.vue` 板块下拉仍缺北交所，可一并补齐。

### ⑧ 外部模型导入门槛过高 —— 真实存在（需修）
- 后端 `POST /api/ml/models/import` 要求上传一个 **joblib 序列化的 dict 包**，内含 `model`（需实现 `.predict(X)`）和 `featureNames`，且**特征名必须与平台 `ml.build_dataset` 产出的特征列完全一致**，否则打分/回测会维度错配崩溃。
- 平台**不提供任何引导/模板**：普通用户既不知道应该包含哪些特征、特征顺序如何，也没有"模型导入向导"或"兼容检查"。结果就是——"导入模型"按钮虽有，但**实际不可用**。
- **修复建议**：① 提供"下载标准特征模板/样例"；② 导入时做 `featureNames` 校验与对齐提示；③ 与 P4 的"人造模型"打通，让平台内手搓的模型可直接导出/再导入。

### ⑨ ML 样本数不足时无友好处理 —— 健壮性缺陷（需修）
平台 ML 流程有 **3 道独立的样本门槛**，分别在三个阶段触发（代码见 `backend/app/ml.py`）：

| 阶段 | 触发门槛（代码位置） | 主要诱因 |
|---|---|---|
| 构建数据集 | 总样本 = 0 抛 `有效样本不足，无法构建数据集（请增大候选池或历史长度）`（`:160`） | poolSize/hist 小、板块池窄（北交所/细分行业）、个股 K 线短（< 60+N 日）、因子缺失 |
| 时序交叉验证 | 分不出 (训练≥50 & 测试≥10) 的折 → 抛 `样本不足以做时序交叉验证`（`:253`）/ `样本不足以完成任何一折训练`（`:290`） | 总样本 N 小、`n_splits` 设太大、`gap` 设太大 |
| ML 回测 | 有效股票 < 15 只（groups×3）抛 `有效股票样本不足`（`:812`）；调仓日截面 < 10 只（groups×2）当天跳过（`:901`）；全程无一天凑够 → 抛 `有效截面样本不足`（`:940`） | 候选池小、个股 K 线 < 40 日、停牌/涨跌停/因子缺失 |

- 单只股票 K 线太短被整只丢弃：`if len(kline) < 60 + n: continue`（`:128`）；因子算不出的切片被丢弃（`:139`）。
- **修复建议**：① 触发时返回**结构化错误**（含当前样本数 / 缺哪些股票 / 建议调哪些参数），而非裸异常；② 前端在提交前**预检样本规模**并提示；③ 自动降级（如 CV 折数动态下调）而非直接失败。

### ⑩ 回测报告生成功能 —— 基础版已实现，但作为完整功能有缺口（需增强）
> 用户需求：提供一个"生成回测报告"的功能。
- **当前已有（基础版）**：
  - 后端 `routers/reports.py`：`POST /api/reports/backtest`（`reports.py:32`），支持 `format=html | excel`，由 `metrics/config/groupSummary/longShort/icSeries` 生成自包含 HTML 或 openpyxl Excel。
  - 前端 `BacktestView.exportReport`（BacktestView.vue:141-154）：回测出结果后点"导出"按钮，调用 `/reports/backtest` 下载 `backtest.html` / `backtest.xlsx`；`MLView.vue:198-208` 也复用同一接口导出 ML 回测报告。
  - 数据库 `db.create_backtest_run`（db.py:272）已预留 `report_path` 字段，但**回测主流程并未把报告落盘到该字段**（见下"缺口"）。
- **作为完整功能的缺口（需增强）**：
  1. **报告不入历史库**：`backtest_runs.report_path` 始终为 `None`，没有"报告列表/历史"可供回看或重下；每次只能"当场导出"。
  2. **导出 HTML 无图表**：页面上有净值曲线/分组柱状图，但导出的 HTML 只有 KPI 卡片 + 表格，**没有 equity curve、回撤图、分组收益图**（纯文本表格，可读性弱）。
  3. **无 PDF 导出**：只有 HTML/Excel，缺正式归档常用的 PDF。
  4. **不覆盖选股结果**：`/api/reports/backtest` 只接收回测 metrics，选股（selection）结果没有对应报告模板。
  5. **依赖在 UI 先跑出 `result`**：报表数据来自 `result.value`，无"从已保存策略/历史运行重新生成报告"的能力。
- **修复建议**：① 回测完成时调用 `create_backtest_run(..., report_path=...)` 落盘并建"报告历史"页；② HTML 报告内嵌 ECharts/Chart.js 图表（复用前端已有图表配置）；③ 增加 PDF 导出（如 weasyprint/playwright）；④ 补"选股结果报告"模板；⑤ 支持从历史运行一键重生成。

## 三、优先级建议（按影响面与改动成本）

| 顺序 | 项 | 优先级 | 理由 |
|---|---|---|---|
| 1 | **P6 日期自定义** | 高 | 纯前端缺控件，后端已就绪，改动最小、价值最大 |
| 2 | **P4 人造/手动模型** | 高 | 用户本次明确诉求；落盘后顺带可解 P5，性价比高 |
| 3 | **P1 北交所单只导入** | 高 | `normalizeCode` 一行逻辑 + 腾讯前缀映射 |
| 4 | **P10 回测报告增强** | 中 | 基础版已有，补齐图表/历史/PDF 即可成完整功能，用户明确要 |
| 5 | **P5 模型→盯盘调度** | 中高 | 打通 ML 与调度断点（依赖 P4） |
| 6 | **P2 期货进模型** | 中 | 需新增期货 K 线 + 资产类别分支，工作量较大 |
| 7 | **P7 行业板块回测** | 中 | 用户核心诉求；后端已有 `fetch_sector_map` 可复用，前端加下拉 + `sector:` 透传 |
| 8 | **P3 新增基础因子** | 中 | 开放因子注册 |
| 9 | **P8 外部模型导入门槛** | 低 | 平台内训练/人造(P4)通路打通后可缓解 |
| 10 | **P9 样本不足友好处理** | 低 | 健壮性，建议在 P4/P7 改完小池场景后一并补 |
