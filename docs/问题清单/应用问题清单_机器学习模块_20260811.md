# 机器学习模块问题核查报告（2026-08-11）

## 核查说明
- 方式：只读代码核查 + 接口轻量实测，未改动任何代码/数据
- 环境：应用运行中（后端 8899 / 前端 5899）
- 范围：后端 `ml.py`、`routers/ml.py`、`scheduler.py`、`reporting.py`；前端 `MLView.vue`、`OptimizeView.vue`、`BacktestView.vue`
- 说明：历史诊断中部分问题已随代码演进修复（见第六节的"已修复"项），本报告以当前实际代码为准

---

## 一、时间段 与 历史长度 对不上（确认存在）

**现象**：用户在界面设定的"回测/训练时间段"与模型实际使用的历史 K 线长度不一致，且前端从不回显真实使用的历史窗口——看起来是"某时间段"，实际拉取的历史远早于此。

**代码信号**：
- 历史长度 `hist` 被静默钳制到 ≥244 天（构造样本所需最小回溯），用户传入的 `hist` 不被尊重
- K 线按"最近 hist 天"拉取（以今日为终点），并不是"从设定的起始日开始算 hist 天"
- 含快照因子且未填起始日时，起始日被静默前移到"60 个交易日前"
- 主回测页同样：设了起始日后仍额外 +240 天历史
- 前端 ML 回测结果只回显"调仓次数 / KPI"，从不展示"实际拉取历史天数 / 有效区间 / 起始日被改写"

**判定**：确实存在。建议回测/评估报告显式返回 `actualHistDays`、`effectiveStart/End` 并对静默钳制/改写给出告警。

---

## 二、平仓 / 调仓 信号缺失（确认，部分存在）

**现象**：ML 模块里找不到"平仓""调仓"这类交易信号；回测页与 ML 页都没有买卖动作列。

**代码信号**：
- 模型回测（`backtest_model`）只算"分组多空收益"，不产出任何离散买卖信号
- 平仓信号仅在盯盘调度里：已持仓且判看空 → 平仓（全平）；但默认 `auto_trade` 关闭（只给信号不成交），且 ML 页面不展示该信号
- 全仓代码没有任何"调仓 / 换仓 / 再平衡"信号类型；模型模式信号集只有 {看多, 看空, 中性, 平仓}，没有减仓、没有换仓

**判定**：平仓信号代码存在但藏在盯盘路径、默认不执行、ML 页面无；"调仓"信号类型确实缺失。若用户说的"平仓"指持仓退出信号——代码有，但不在 ML 页面；若"调仓"指换仓/部分减仓/再平衡——确实缺失。

---

## 三、手动调参初始值都是 1（确认存在）

**现象**：在 ML 页打开"调参"面板时，所有因子权重输入框初始值都是 1（等权）。

**代码信号**：
- 人工调参面板初始化：`featureWeights[f] = 已存权重 ?? 1`，即模型没有已存权重时每个因子默认填 1
- 对比"新建人造模型"的权重默认是 0（不参与），两处默认值不一致

**判定**：确实存在。默认全 1 会让"调参"初始就是等权，且某些本不该参与的因子被强制纳入；建议默认用模型特征重要性或 0。

---

## 四、调参后没有保存到一个新模型里（确认存在）

**现象**：无论"人工调参"还是"Optuna 寻优"，界面上都没有一个明确的"保存为新模型"动作 / 记录。

**代码信号**：
- 人工调参（ML 页"调参"）保存后生成 `adjustId` 覆盖原模型、复用原模型 id，不产生独立新模型
- OptimizeView（Optuna 寻优）结果只有"回写为策略""应用到回测"两个按钮，没有"保存为新模型"；后端寻优内部虽会落盘一个时间戳命名的新模型文件，但前端不展示、不刷新模型列表，用户感知为"没存"

**判定**：确实存在。建议人工调参提供"另存为新模型"、寻优结果提供"保存最优参数模型"并刷新列表。

---

## 五、回测报告没有图表 / 没有仓位的变化过程（确认，部分）

**现象**：回测报告里看不到"仓位 / 持仓变化过程"；用户感知"报告没有图表"。

**代码信号**：
- 导出 HTML 报告（`reporting.py`）本身含 3 个 ECharts 图：多空累计收益与回撤、分组平均收益、IC / RankIC（`echarts.min.js` 本地存在，可离线渲染）
- 但所有图都是"分组多空组合"视角，**没有"单个模拟组合的仓位 / 持仓变化过程"图或序列**
- 回测引擎（`backtest_model`）只维护分组多空收益点，不维护持仓台账，所以"仓位变化过程"在数据结构上就缺失

**判定**："完全无图"不成立（报告有图）；但"没有仓位变化过程"成立——因引擎不算持仓。若用户在某个具体视图看到空白图，可能是该视图未接入图表组件，需另查。

## 六、其他 ML 量化逻辑缺陷

1. **快照因子前视（确认，已告警但风险仍在）**：含快照因子时，因子最新值被应用到回测所有历史截面（beginning-of-sample look-ahead bias），回测绩效系统性高估。代码已加 `snapshotWarning` 提示，但风险未消除——实盘因子应全部使用历史时序特征。
2. **候选池生存偏差（确认，已告警）**：回测候选池为当前上市股票快照，已退市股票不在池内，历史收益系统性高估。代码已加 `survivorshipBiasWarning`。
3. **无持仓台账 / 无离散信号（确认）**：ML 回测只算分组多空，既无个股买卖过程、也无平仓 / 调仓动作，无法支撑"组合层"的实盘映射。
4. **年化 / 采样数修正已做**（`ml.py` 调仓间隔 n 日 → 年化采样数 = 252/n）：旧的"年化收益高估 n 倍、Sharpe 高估 √n 倍"已修复。
5. **Purged Walk-Forward 已演进**（`purged_walk_forward_split_by_dates`）：按交易日 `gap_days` 隔离 train/test，旧的"gap 按样本序号失效"已修复。
6. **`/ml/optimize` 端点**（routers）在数据集构建 / 寻优异常时会抛 502；但前端 OptimizeView 实际走 `/jobs`（kind=ml-optimize）异步，较稳。直接调用该端点仍可能 502。
7. **带模型回测（/api/ml/backtest）**：历史诊断曾报崩溃，本次未触发完整回测复测，建议后续实跑确认是否仍存在问题。

## 修复优先级建议（供参考）
- **P0**：时间段 / 历史长度不透明（误导用户对回测区间的判断）；无持仓台账导致无仓位变化过程
- **P1**：手动调参默认全 1；调参后无"另存新模型"；平仓 / 调仓信号缺失
- **P2**：快照因子前视（已有告警）、生存偏差（已有告警）作为已知风险提示保留
